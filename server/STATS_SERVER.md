# Задание: сервер статистики и рекордов для «Лазер 3D»

Это инструкция для сессии, у которой есть доступ к VDS и домену. Нужно поднять на VDS небольшой сервис
с базой данных и HTTP API. Его будет вызывать статический сайт https://klouner.github.io/laser-sailing-sim/
(парусный тренажёр, код в публичном репозитории `klouner/laser-sailing-sim`). Сейчас статистика и рекорды
пишутся в форму Google; их надо перенести на свой сервер, чтобы видеть IP, модель устройства и всё остальное.

Клиентскую часть (код сайта) делает другая сессия. Ей нужен только результат из раздела
«Что прислать обратно» в конце. Контракт ниже менять нежелательно: под него уже пишется клиент.
Если что-то из него сделать нельзя, сделай иначе и опиши отличие в ответе.

## 1. Требования к размещению

- HTTPS с действующим сертификатом обязателен: сайт открыт по HTTPS, обычный HTTP браузер заблокирует.
- Адрес: отдельный поддомен (например `laser-api.<домен>`) или путь на существующем домене
  (например `https://<домен>/laser-api`). Выбери то, что проще на этом сервере. Дальше это называется `BASE`.
- Сервис слушает только `127.0.0.1`, наружу его отдаёт уже стоящий на сервере прокси (nginx или Caddy).
  Если прокси нет, поставь Caddy.
- Другие сайты и службы на VDS не трогать. Перед правкой конфигов прокси посмотри, что там уже есть.
- Запуск через systemd, автозапуск после перезагрузки, логи в journald.
- Стек на твой выбор, без тяжёлых зависимостей: Node.js 18+ или Python 3.10+, база SQLite в режиме WAL.
  Нагрузка маленькая: десятки посетителей в день, до нескольких запросов в минуту от каждого.

## 2. Настоящий IP посетителя

Это главное, ради чего всё делается.

- Прокси должен передавать сервису адрес клиента (`X-Forwarded-For` или `X-Real-IP`).
- Сервис берёт адрес из этого заголовка, только если соединение пришло с `127.0.0.1`. Иначе берёт адрес сокета.
- Проверь на деле: запрос с внешней машины должен записать в базу её внешний адрес, а не `127.0.0.1`.
- Если легко подключается офлайн-база GeoIP, добавь страну и город. Это необязательно.

## 3. Публичное API

Все пути относительно `BASE`. Запросы приходят из браузера со страницы `https://klouner.github.io`.

### CORS, общий для всех публичных путей

- `Access-Control-Allow-Origin: https://klouner.github.io` (ровно так, без слэша и без пути) и `Vary: Origin`.
- `Access-Control-Allow-Methods: GET, POST, OPTIONS`, `Access-Control-Allow-Headers: Content-Type`.
- На `OPTIONS` отвечать `204`.
- Cookies и авторизации нет. `Cache-Control: no-store` на всех ответах.

### `POST /event` — событие статистики

- Тело: один объект JSON, не больше 4096 байт.
- **Важно:** заголовок будет `Content-Type: text/plain;charset=UTF-8`. Так браузер шлёт `sendBeacon`
  и так запрос уходит без предварительного `OPTIONS`. Тело надо разбирать как JSON при любом `Content-Type`.
- Ответ: `204` без тела. Клиент ответ не читает.
- Ошибки: `400` не JSON, `413` слишком большое тело, `429` превышен лимит.
- Лимит: 120 событий в минуту с одного IP.
- Неизвестные поля и неизвестные значения `type` не отклонять: сохранять как есть. Клиент будет развиваться.

Общие поля каждого события:

| Поле | Тип | Смысл |
|---|---|---|
| `v` | число | версия формата, сейчас `1` |
| `vid` | строка до 40 | постоянный идентификатор посетителя, случайный UUID из localStorage |
| `sid` | строка до 40 | идентификатор сеанса, новый UUID на каждую загрузку страницы |
| `type` | строка до 20 | `open`, `ping`, `close`, `lesson`, `race` |
| `t` | число | секунд активного времени с начала сеанса |
| `seq` | число | порядковый номер события в сеансе |

Дополнительные поля по типам. Любое может отсутствовать.

- `open`, один раз при загрузке: `ua`, `model`, `platform`, `platformVersion`, `browser`, `screen` (например `"390x844"`),
  `dpr`, `gpu`, `lang`, `tz`, `ref`, `utm`, `webview` (true/false), `touch` (true/false).
- `ping`, каждые 30 секунд, пока вкладка видима, и `close` при уходе: `fps`, `quality`, `mode`, `cam`.
- `lesson`: `id` (строка), `result` (`done` или `failed`).
- `race`: `time` (секунды).

Сервер сам добавляет к каждому событию время в UTC и IP.

### `GET /top?ver=3` — рекорды гонки

- `ver` — версия физики лодки, целое число. Рекорды разных версий не смешиваются.
- Ответ `200`, JSON-массив до 10 записей по возрастанию времени:
  `[{"name":"Иван","time":151.2,"date":"2026-11-10"}]`

### `POST /submit` — записать рекорд

- Тело JSON, `Content-Type` тоже будет `text/plain`: `{"name":"Иван","time":151.2,"ver":3,"vid":"…","sid":"…"}`
- Проверки: `name` обрезать до 18 символов, убрать управляющие символы и `<>`, пустое заменить на `Без имени`.
  `time` от 20 до 3600, иначе `400`. Не чаще одной записи в 10 секунд с одного IP, иначе `429`.
- Ответ `200`: тот же массив, что отдаёт `GET /top` для этой `ver`, уже с новой записью.

### `GET /health`

Ответ `200`: `{"ok":true}`.

## 4. База данных

SQLite, один файл, например `/var/lib/laser-stats/stats.db`. Схема по смыслу такая, детали на твоё усмотрение:

- `events`: `id`, `ts`, `ip`, `vid`, `sid`, `type`, `t`, `data` (исходный JSON целиком).
- `sessions`: одна строка на `sid`, обновляется при каждом событии. Поля: `vid`, `ip`, страна и город, если есть,
  `first_ts`, `last_ts`, `active_sec` (максимальный `t`), все поля из `open`, последние `fps` и `quality`,
  число событий, список пройденных уроков.
- `records`: `id`, `ts`, `ver`, `name`, `time`, `vid`, `sid`, `ip`.

Ежедневная резервная копия файла базы, хранить последние 14 штук.

## 5. Закрытая часть для владельца

Страница `BASE/admin` под паролем (Basic auth или токен в адресе). Пароль сгенерируй и отдай владельцу.

- Сводка по дням: открытий, уникальных посетителей по `vid`, уникальных IP, среднее и суммарное время.
- Таблица сеансов, новые сверху: время, IP, страна и город, устройство и модель, система, браузер, экран,
  видеокарта, откуда пришёл, длительность, пройденные уроки, кадров в секунду и качество графики.
- Фильтр по датам, выгрузка в CSV.

Вёрстка простая, одной HTML-страницей, без внешних библиотек.

## 7. Проверка

Выполни с внешней машины, не с самого VDS, подставив свой `BASE`:

```bash
BASE=https://…        # без слэша в конце
O='Origin: https://klouner.github.io'

# 1. событие: ожидается 204 и заголовок Access-Control-Allow-Origin
curl -si -X POST "$BASE/event" -H "$O" -H 'Content-Type: text/plain;charset=UTF-8' \
  --data '{"v":1,"vid":"test-vid","sid":"test-sid","type":"open","t":0,"seq":0,"ua":"curl","screen":"1x1"}' | head -12

# 2. рекорды: ожидается 200 и JSON-массив
curl -si "$BASE/top?ver=3" -H "$O" | head -12

# 3. запись рекорда: ожидается 200 и массив с записью «Проверка»
curl -si -X POST "$BASE/submit" -H "$O" -H 'Content-Type: text/plain;charset=UTF-8' \
  --data '{"name":"Проверка","time":999.9,"ver":0,"vid":"test-vid","sid":"test-sid"}' | head -12

# 4. предварительный запрос: ожидается 204
curl -si -X OPTIONS "$BASE/event" -H "$O" -H 'Access-Control-Request-Method: POST' | head -8
```

После проверки убедись в админке, что у тестового события записан внешний IP машины, с которой шёл запрос.
Тестовый рекорд записан с `ver=0`, на сайт он не попадёт.

## 8. Что прислать обратно

Пришли владельцу этот блок с заполненными значениями. Он передаст его сессии, которая делает сайт.
**Пароль от админки и любые другие секреты в этот блок не включай:** код сайта публичный.

```
LASER_API_BASE=https://…            # без слэша в конце
EVENT_PATH=/event
TOP_PATH=/top
SUBMIT_PATH=/submit
CORS_ORIGIN=https://klouner.github.io
MAX_BODY_BYTES=4096
EVENT_RATE_LIMIT=120/min
REAL_IP_CHECKED=да | нет           # внешний IP в базе совпал с адресом тестовой машины
GEOIP=да | нет
RECORDS_IMPORTED=<число> | нет
SERVER_COUNTRY=<страна, где стоит VDS>
ОТЛИЧИЯ ОТ КОНТРАКТА=нет | <что сделано иначе>
```

И под блоком вывод четырёх команд из раздела 7 как есть.

Владельцу отдельно, не для передачи дальше: адрес админки и пароль, путь к файлу базы, имя службы systemd.
