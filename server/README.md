# Сервер статистики и рекордов

Сайт «Лазер 3D» статический и своей базы не имеет. Статистику посещений и общую таблицу рекордов гонки
хранит отдельный сервис на VDS владельца.

| | |
|---|---|
| Адрес | `https://sh38.ru/laser-api` |
| Где задан на сайте | `API` в `js/config.js` |
| Сервер | VDS в Бангкоке, nginx, сервис слушает только `127.0.0.1` |
| База | SQLite на самом сервере |
| Админка | `https://sh38.ru/laser-api/admin`, вход по паролю. Пароль есть только у владельца |

**Кода сервера в этом репозитории нет.** Он написан и развёрнут отдельной сессией прямо на VDS по заданиям
[STATS_SERVER.md](STATS_SERVER.md) и [STATS_SERVER_2.md](STATS_SERVER_2.md). Эти два файла остаются как история
постановки. Актуальное описание того, что работает сейчас, находится в этом документе.

## 1. Публичное API

Все пути относительно `https://sh38.ru/laser-api`.

| Метод и путь | Назначение | Ответ |
|---|---|---|
| `POST /event` | событие статистики | `204` без тела |
| `GET /top?ver=N` | десять лучших результатов гонки для версии физики `N` | `200`, JSON-массив |
| `POST /submit` | записать результат гонки | `200`, обновлённый массив |
| `GET /health` | состояние и общие счётчики | `200`, JSON-объект |

**Общие правила.**

- Запросы разрешены только странице с адреса `https://klouner.github.io`: сервер отвечает заголовком
  `Access-Control-Allow-Origin` ровно с этим значением.
- Тело `POST` это JSON, но заголовок у него `Content-Type: text/plain;charset=UTF-8`. Такой запрос браузер
  отправляет сразу, без предварительного `OPTIONS`, и его умеет слать `navigator.sendBeacon`.
  Сервер разбирает тело как JSON при любом `Content-Type`.
- Тело не больше 4096 байт.
- Лимит: 120 событий в минуту с одного IP, одна запись рекорда в 10 секунд с одного IP. Превышение даёт `429`.
- Cookies и авторизации нет. Все ответы с `Cache-Control: no-store`.
- Неизвестные поля и типы событий сервер сохраняет как есть.

## 2. События статистики

Отправляет `js/analytics.js`. Каждое событие содержит общие поля:

| Поле | Смысл |
|---|---|
| `v` | версия формата, сейчас `1` |
| `vid` | номер посетителя: случайный UUID, хранится в `localStorage` браузера |
| `sid` | номер сеанса: новый UUID на каждую загрузку страницы |
| `type` | тип события |
| `t` | секунд активного времени с начала сеанса. Считается, только пока вкладка видима |
| `seq` | порядковый номер события в сеансе |

Сервер сам добавляет время в UTC и IP-адрес.

| `type` | Когда | Дополнительные поля |
|---|---|---|
| `open` | один раз после загрузки страницы | описание устройства, см. ниже |
| `ping` | каждые 30 секунд, пока вкладка видима | `fps`, `quality`, `mode`, `cam` |
| `close` | вкладка скрыта или закрыта | `fps`, `quality`, `mode`, `cam` |
| `lesson` | урок начат | `id`, `result: "start"` |
| `lesson` | урок пройден или провален | `id`, `result: "done"` или `"failed"`, `sec`, при оверкиле `why: "capsize"` |
| `race` | гонка начата | `result: "start"` |
| `race` | финиш гонки | `result: "finish"`, `time` в секундах |
| `debug` | страница открыта с `?debug=1` | нет |

Значения полей:

- `fps`: средняя частота кадров за последнюю секунду;
- `quality`: `low`, `med` или `high`;
- `mode`: `free`, `race` или `lesson:<id урока>`;
- `cam`: `chase`, `top`, `side`, `cockpit`, `free`;
- `id` урока: `irons`, `trim`, `tack`, `gybe`, `beat`, `stop`, `gust`, `trimsail`, `roll`, `start`, `spin`;
- `sec`: сколько секунд длился урок.

Финиш гонки отправляется всегда, даже если результат не попал в десятку. Запись в таблицу рекордов идёт
отдельным запросом `POST /submit` и только если посетитель вписал имя.

Пример события:

```json
{"v":1,"vid":"4e036475-941a-44a1-a440-9420469afa1f","sid":"e6f0cf1c-65d9-474b-964a-a87062f5f31f",
 "type":"ping","t":61,"seq":3,"fps":58,"quality":"high","mode":"lesson:tack","cam":"chase"}
```

## 3. Что известно о посетителе

Поля события `open`:

| Поле | Пример | Откуда |
|---|---|---|
| `ua` | строка браузера | `navigator.userAgent` |
| `platform` | `Android`, `iOS`, `Windows`, `macOS`, `Linux` | строка браузера |
| `platformVersion` | `14` | строка браузера или сам браузер |
| `model` | `SM-G991B`, `iPhone` | см. ниже |
| `browser` | `Chrome 131`, `Safari 17`, `Яндекс 24` | строка браузера |
| `screen` | `390x844` | размер экрана |
| `dpr` | `3` | плотность пикселей |
| `gpu` | название видеокарты | WebGL |
| `lang` | `ru-RU` | язык браузера |
| `tz` | `Europe/Moscow` | часовой пояс |
| `ref` | адрес страницы, с которой пришли | `document.referrer` |
| `utm` | параметры из адреса сайта | строка запроса |
| `webview` | `true`, если сайт открыт внутри Telegram, VK, Instagram | строка браузера |
| `touch` | `true` для сенсорного экрана | браузер |

**Модель устройства.** Точную модель сообщают только браузеры на Chromium, в основном на Android.
iPhone и iPad модель не раскрывают: будет `iPhone`, версия iOS и размер экрана, по которому модель можно
прикинуть. На компьютерах модели нет, есть система, браузер и видеокарта.

**IP, страна и город.** IP сервер берёт из запроса. Страну и город он определяет запросом
к стороннему сервису `ip-api.com`: они появляются в сеансе через несколько секунд после первого события.
Если сервис недоступен, сеанс сохраняется без них.

**Кого статистика не видит.** Посетителей с блокировщиком, который режет запросы к `sh38.ru`,
и тех, у кого браузер запрещает `localStorage`: у них номер посетителя каждый раз новый.

## 4. Рекорды

`GET /top?ver=3` отдаёт до десяти записей по возрастанию времени:

```json
[{"name": "Макс", "time": 143.1, "date": "2026-11-10"}]
```

`POST /submit` принимает:

```json
{"name": "Иван", "time": 151.2, "ver": 3, "vid": "…", "sid": "…"}
```

Проверки на сервере: имя обрезается до 18 символов, управляющие символы и `<>` удаляются, пустое имя
заменяется на «Без имени». Время от 20 до 3600 секунд.

**Версия физики `ver`.** Результаты, полученные на разной модели лодки, несравнимы. Каждая версия хранит
свою таблицу. Сейчас на сайте `ver = 3`, значение задано в `API.ver` в `js/config.js`. При изменении физики,
влияющем на скорость, версию нужно поднять: таблица начнётся заново, старые записи останутся в базе.

Несколько результатов одного имени могут стоять в таблице подряд: сервер их не объединяет.

`ver = 0` используется для проверочных записей. На сайте они не показываются.

## 5. Админка

`https://sh38.ru/laser-api/admin`, вход по паролю.

Админку делала серверная сессия, её кода в этом репозитории нет. Что в ней есть:

- **Сеансы.** Колонки таблицы: начало, IP, страна и город, устройство, система, браузер, экран, видеокарта,
  откуда пришёл, время на сайте, уроки, гонка, частота кадров, качество графики, язык, номер посетителя.
- **Гонки** и **Уроки.** Добавлены по второму заданию: старты и финиши гонок с результатами,
  по каждому уроку число начатых, пройденных и проваленных попыток.
- Время показывается в часовом поясе того, кто смотрит админку.
- Выгрузка в CSV предусмотрена первым заданием.

Раскрытие сеанса в список событий, сводка сверху и показ последних 7 дней по умолчанию были в задании
[STATS_SERVER_2.md](STATS_SERVER_2.md). Серверная сессия отчиталась о готовности разделов, но эти три детали
отдельно не подтверждала: проверьте их в самой админке.

Доступ к серверу, путь к файлу базы, имя службы и пароль от админки находятся у владельца.
В репозиторий и в код сайта они не попадают: репозиторий публичный.

## 6. Проверка работы

**Снаружи, без пароля.** Общие счётчики:

```bash
curl -s https://sh38.ru/laser-api/health
# {"ok": true, "events": 8, "sessions": 2, "records": 2, "last_event": "2026-11-11T04:19:36Z"}
```

Если после посещения сайта `events` и `last_event` не меняются, события до сервера не доходят.

**С устройства посетителя.** Откройте сайт с параметром `?debug=1`:

`https://klouner.github.io/laser-sailing-sim/?debug=1`

Посередине экрана появится сообщение. «Сервер ответил 204» означает, что всё работает.
«Запрос до сервера не дошёл» означает, что его режет блокировщик или сеть.

**Запросами.** Заголовок `Origin` обязателен для проверки CORS:

```bash
B=https://sh38.ru/laser-api
O='Origin: https://klouner.github.io'
curl -si -X POST "$B/event" -H "$O" -H 'Content-Type: text/plain;charset=UTF-8' \
  --data '{"v":1,"vid":"test-1","sid":"test-1","type":"open","t":0,"seq":0,"utm":"?utm_source=selftest"}' | head -8
curl -si "$B/top?ver=3" -H "$O" | tail -2
```

Проверочные события помечайте `vid` и `sid`, начинающимися с `test-` или `selftest`, либо `utm_source=selftest`:
по этим признакам их потом легко удалить из базы.

**Типичная причина «статистики нет».** Браузер посетителя ещё держит прежнюю версию сайта: GitHub Pages
разрешает кэшировать файлы 10 минут. Номер версии написан внизу панели настроек сайта.

## 7. Приватность

- Сайт сообщает о сборе статистики строкой внизу панели настроек.
- Cookies не используются. Посетитель узнаётся по случайному номеру в `localStorage` его браузера.
- IP-адрес считается персональными данными. Сервер находится в Таиланде. Для посетителей из России
  закон требует хранить такие данные в России. Владельцу стоит уточнить этот вопрос у того,
  кто в школе отвечает за персональные данные.
- IP каждого посетителя уходит третьей стороне, сервису `ip-api.com`, чтобы определить город. Этого можно
  избежать, поставив на сервер офлайн-базу GeoIP: пункт 6 в [STATS_SERVER_2.md](STATS_SERVER_2.md).
- Срок хранения данных не задан.

## 8. Если сервер недоступен

Сайт продолжает работать.

- События статистики теряются молча.
- Таблица рекордов читается из `localStorage` браузера. Новый рекорд сохраняется там же и на сервер
  позже не досылается.

Чтобы отключить сервер совсем, поставьте в `js/config.js`: `export const API = null;`.

При запуске сайта с `localhost` сервер не используется. Параметр `?api=1` включает его и там.

## 9. Запасные варианты без своего сервера

В коде сайта остались прежние способы хранить общую таблицу рекордов. Они включаются в `js/config.js`,
только если `API = null`. Статистику посещений они не собирают.

| Вариант | Как включить | Файлы |
|---|---|---|
| Google Форма с Таблицей | `GFORM = { action, nameEntry, timeEntry, csv }` | нет |
| Публичный блоб jsonblob.com | `LEADERBOARD_URL = 'https://jsonblob.com/api/jsonBlob/<id>'` | нет |
| Простой сервер рекордов на Node.js | `LEADERBOARD_URL = 'https://ваш-домен'` | `leaderboard-server.js`, `laser-leaderboard.service`, `Caddyfile`, `nginx.conf` в этой папке |
| Cloudflare Worker | `LEADERBOARD_URL = 'https://….workers.dev'` | `worker/leaderboard-worker.js` |

Простой сервер рекордов это один файл без зависимостей: `GET /top`, `POST /submit`, `GET /health`,
данные в JSON-файле. Запуск:

```bash
PORT=8787 DATA=/var/lib/laser-leaderboard/top.json ORIGIN=https://klouner.github.io node leaderboard-server.js
```

Версии физики он не различает и статистику не принимает. Для новой установки лучше повторить нынешний сервер
по заданию [STATS_SERVER.md](STATS_SERVER.md).
